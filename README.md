# MenuFlow AI

MenuFlow AI turns any restaurant menu into something a real person can actually use.

Most menu tools stop at translation. That is not the real problem. The real problem is standing in front of a menu written in a language you do not speak, describing dishes from a cuisine you do not know, inside a culture you may never have been exposed to, while needing to decide what to order in a few minutes.

MenuFlow AI solves that gap. A user sends a menu photo through Telegram, the app analyzes it, structures every dish, explains what it likely is, flags possible allergens, estimates spiciness, generates dish visuals, and publishes a clean web page that can be shared with anyone. The same menu can also be opened as a personalized view for a specific user based on their allergies, spice tolerance, dietary preferences, and food dislikes.

It is not just menu translation. It is a day-to-day decision tool for eating confidently in unfamiliar places.

## The Problem

Restaurant menus are often inaccessible in ways that standard translation does not fix:

- The language is unfamiliar.
- The cuisine is unfamiliar.
- Dish names are culturally specific and ambiguous.
- Ingredients and allergens are rarely obvious.
- Users cannot picture what will actually arrive at the table.
- Dietary restrictions and spice tolerance are hard to apply under time pressure.

This creates friction at exactly the wrong moment: when someone is hungry, in a restaurant, and trying to make a fast decision without making a mistake.

## Our Solution

MenuFlow AI combines Telegram-first input with AI-powered menu understanding.

- The user sets their profile once in Telegram: allergies, spice tolerance, diet, and food preferences.
- They send a menu photo to the bot.
- The app extracts and explains the menu into structured dishes.
- A generic public menu page is created instantly so it can be shared with friends.
- A personalized version is created for the sender using their saved profile.
- Friends can open the generic page and personalize it for themselves with their own profile token.
- Dish images are generated in the background so users can understand what a plate may actually look like before ordering.

This makes the product useful in real life, not just technically impressive.

## Why Telegram First

Telegram is the right front door for this product:

- no separate onboarding-heavy app flow
- easy to send a menu the moment you sit down
- natural place to collect profile preferences once
- easy to return both a generic and personalized link
- convenient for sharing a menu with other people at the table

The website is intentionally lightweight. Its main job is to display generated menus beautifully and let people personalize shared menus when needed.

## What The App Does Today

- Accepts menu photos through Telegram
- Extracts structured dish data with Gemini
- Infers likely ingredients and possible allergens
- Tags dishes by spiciness
- Adds explicit vegan and vegetarian flags
- Generates dish images
- Stores menus in Upstash Redis
- Publishes a generic shareable menu page
- Publishes personalized menu views based on Telegram profiles

## Product Positioning

MenuFlow AI is for people who want to order with confidence when a menu is unfamiliar.

It helps when:

- you do not speak the language
- you do not understand the cuisine
- you have allergies or dietary restrictions
- you want to avoid ordering blindly
- you want to know what a dish likely is before it reaches the table

The product sits at the intersection of travel, food discovery, accessibility, and AI-assisted decision-making.

## User Experience

1. The user sets up their preferences in Telegram.
2. The user sends a menu photo.
3. MenuFlow AI analyzes the image and builds a structured menu.
4. The app creates:
   - a generic menu link for sharing
   - a personalized menu link for the sender
5. The user opens the menu page and sees dishes, explanations, spice tags, allergen warnings, and generated images.
6. Anyone else opening the generic page can click `Personalize for me` and apply their own saved profile.

## Environment Variables

The app expects:

- `GEMINI_API_KEY` for menu extraction
- `GEMINI_MODEL` optional override for the primary extraction model
- `GEMINI_FALLBACK_MODELS` optional comma-separated fallback models for extraction retries
- `NANOBANANA_API_KEY` optional image generation key, falling back to `GEMINI_API_KEY`
- `NANOBANANA_MODEL` optional image generation model override
- `UPSTASH_REDIS_REST_URL` for the live menu datastore
- `UPSTASH_REDIS_REST_TOKEN` for the live menu datastore
- `TELEGRAM_BOT_TOKEN` for Telegram bot messaging and onboarding
- `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME` for Telegram deep links from public menu pages
- `NEXT_PUBLIC_APP_URL` for absolute links generated by the bot
- `NEXT_PUBLIC_IMAGE_GEN_RPM` optional image generation pacing

Image generation uses `NANOBANANA_API_KEY` when available and falls back to `GEMINI_API_KEY`.

## Data And Links

- Generic public menu route: `/menu/:id`
- Personalized public menu route: `/menu/:id/p/:profileToken`

Menus are stored in Upstash Redis. Telegram user profiles are also stored in Redis and linked through compact public profile codes.

## Upstash Redis Setup

1. Create a Redis database in Upstash.
2. Open the database details page.
3. Copy:
   - `UPSTASH_REDIS_REST_URL`
   - `UPSTASH_REDIS_REST_TOKEN`
4. Put both values into your local `.env.local`.

## Vercel Deployment

1. Push the repository to GitHub.
2. Import the repo into Vercel.
3. In the Vercel project settings, add these environment variables:
   - `GEMINI_API_KEY`
   - `GEMINI_MODEL`
   - `GEMINI_FALLBACK_MODELS`
   - `NANOBANANA_API_KEY`
   - `NANOBANANA_MODEL`
   - `UPSTASH_REDIS_REST_URL`
   - `UPSTASH_REDIS_REST_TOKEN`
   - `TELEGRAM_BOT_TOKEN`
   - `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME`
   - `NEXT_PUBLIC_APP_URL`
   - `NEXT_PUBLIC_IMAGE_GEN_RPM`
4. Redeploy after saving the env vars.

## Notes

- The app is Telegram-first by design.
- The website is primarily for generated menu pages and personalization views.
- Generic and personalized pages are built on the same canonical menu data.
- Personalization is applied as a user-specific interpretation of the menu, not a destructive rewrite of the original menu.
